# 常见问题

## 部署与环境

**Q：需要 API Key 吗？**
不需要。你在网页版对话里跑也行，把结果复制下来即可。有 API 只是省了复制粘贴。

**Q：能跑在 Mac / Linux 上吗？**
四个脚本是 PowerShell。逻辑很简单（建目录 / 调 pandoc / 解压 docx 数元素），重写成 bash 约 100 行。每个脚本顶部注释写了它做的事，照着写就行。核心资产 `docs/SKILL-原版提示词.md` 完全跨平台。

**Q：一定要用 PowerShell 5.1 吗？**
5.1 和 7 都能跑。但 `.ps1` 必须存成 **UTF-8 带 BOM**，否则 5.1 会按 GBK 解析中文，直接语法错误。仓库里的是带 BOM 的，你自己改完要补回去：

```powershell
$c = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p, $c, (New-Object Text.UTF8Encoding($true)))
```

## 内容生成

**Q：模型输出的结构跟范本对不上怎么办？**
两个办法，按效果排序：
1. 把 `examples/` 里对应学科的范本**贴给它**，并说"结构、栏目顺序、详略程度全部对齐这个范本"。
2. 把结构直接写进指令（`docs/SKILL-原版提示词.md` 里有完整结构模板），不让它自由发挥。

**Q：答案被写进学案了怎么办？**
这是本项目最高频的问题。规格里答案必须**单独成节**并注明「以下内容只写入教案」。交付前 grep 一次：学案里 `答案：` 应为 0 处。

**Q：题目它自己编的，不是我给的。**
指令里要写死：「题目必须来自我提供的材料，我给你的题一字不改；我没给的题不要自己造。需要补充例题时先问我。」
用户只给知识点不给题时，明确让它先问。

**Q：模型算错了怎么办？**
**必查，不能省。** 尤其多解题（"不相似"有多种情况）、最值题、带分类讨论的题。建议：数值题用计算器/脚本复算，几何题建系验算，答案对不对得上一眼能看出来的也别跳过——模型会自信地给错答案。

**Q：一节课要出多少题？**
参考范本：课堂练习 6–8 道（每题型 1–2 道）+ 拓展 4–6 道 + 课后作业 A 组按题型各 1 道 + B 组 2–4 道。多了课上讲不完，少了练不够。

## 排版与转换

**Q：公式在 docx 里变成普通文字了。**
md 里公式必须用 `$...$` 包裹，例如 `$v = gt$`。写成 `v = gt` 或 `½gt²` 都不会转成 Word 公式对象。
自检里 `mdMath > 0` 但 `oMath = 0` 就是这个病。

**Q：图片没进 docx。**
pandoc 按**当前工作目录**解析相对路径，不是按 md 所在目录。`build-lesson.ps1` 已经自动加了 `--resource-path`，如果你是手动调 pandoc，必须自己加：

```powershell
pandoc -f markdown -t docx --resource-path="D:\...\自由落体运动;D:\...\自由落体运动\figs" -o x.docx x.md
```

**Q：几何图怎么画？**
默认没有 matplotlib 的环境下，用 Pillow 手绘（坐标变换 + 直角符号 + 中文字体 `C:\Windows\Fonts\msyh.ttc`），导出 PNG 后 `![](figs/x.png){width=45%}` 引用。**图必须在转 docx 之前画好。**

**Q：字体/行距不对。**
换 `templates/paper-reference.docx`。用法：

```powershell
pandoc -f markdown -t docx --reference-doc=templates\paper-reference.docx -o x.docx x.md
```

默认：宋体 12pt 正文、1.5 倍行距、首行缩进 2 字符、黑体标题。

**Q：教案超过 200 行了。**
说明混进了旁白。grep 这几个词：`时间分配`、`追问`、`评分点`、`批改关注`、`重难点`、`学情`、`分钟`。有就删。

## 流程

**Q：学案和课后作业的答案谁来对？**
课后作业文档里不放答案。三件套打出来后，老师手上是教案，学生手上是学案和作业。下次课由老师对着教案报答案。

**Q：上完课要把文件删掉吗？**
用 `close-lesson.ps1`：清空文件、**保留文件夹**（文件夹本身是进度记录），并登记进 `学生已知数据.md` 的「清理记录」。想先看要删什么，加 `-DryRun`。

**Q：学生多的话怎么管？**
根目录下每个学生一个文件夹，各带 `备课主档.md` + `学生已知数据.md`。定期跑 `lesson-health.ps1` 体检。

**Q：能给它加个 Web 界面吗？**
可以，但先想清楚要解决什么问题。这个项目的价值在**格式规则**，不在界面。加界面之前先跑通一个完整章节——很多人卡在"想做个产品"，而不是"今晚要备课"。

## 关于定位

**Q：这跟 EDUagent / DeepTutor 那些项目什么关系？**
它们偏学校端/学生端，或需要大量数据训练。这个项目偏**一个独立家教老师的单章备课**：不要账号、不要服务器、不要训练，要的是"今晚这节课的三份纸"。

**Q：为什么不做成产品？**
一旦做成产品，就要处理多租户、权限、计费、模板市场……而它现在的形态解决的是一个具体的人的具体问题。**先解决一个人，再谈解决一类人。**

**Q：能商用吗？**
MIT 协议，可以。但请保留对模型答案的人工验算——这不是法律问题，是学生会不会学错的问题。
