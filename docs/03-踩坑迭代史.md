# 踩坑迭代史：从手工管提示词到现在的版本

> 这份文档是项目最值钱的部分。市面上教程只讲"怎么做成"，这份讲**中间失败了什么、为什么失败**。
> 你复制我的成品，可能省 2 小时；你读这段，可能省 2 个月。

时间线：约 2025 年底 → 2026 年 10 月，每天用，两个学生（k60 数学 11 章、k67 数学 10 章 + 物理 7 章）。

---

## 阶段 0：纯手工写提示词（最苦，也是最必要的）

**做法**：每次备课，打开对话框，现写一段提示词：「你是一位有 10 年经验的高中物理老师，请为……输出学案，要求……」然后手动复制结果、手动排版、手动转 docx。

**结果**：能出东西，但每次都要重写提示词，**同一个坑每次重踩一遍**。最典型的是格式漂移——第一次产出的栏目顺序和第三次完全不同，同一个学生的资料前后不一致。

**得到的结论（后来所有设计都基于它）**：
> 提示词不能每次现写。必须固化成"结构模板"，并且让模型先读范本再动笔。

这个结论直接变成了后来 SKILL 里的第一条硬规则：**写任何新资料前，必须先完整读取范本文件**。

## 阶段 1：交给 OpenCode 出稿（失败，但踩出了最有价值的一条链）

**做法**：把三件套的出稿交给一个独立进程（OpenCode + 免费模型）干，我只看结果。

**结果**：**能写文件，但会抄错答案**。一次错题精讲，13 道变式题里它改错了 2 道——「不相似」有多种情况被它简化成一种，另一道正确值根本不在选项里。

**根因不是模型笨，是规格没写清。** 复盘下来有三个具体失效模式：

| 失效模式 | 现象 | 修法 |
|---|---|---|
| 答案被抄进学案 | 规格里写了「答案：…」，它原样抄进学生版 | 答案**单独成节**，注明「以下只写入教案」 |
| 说明句被抄进正文 | 写了「图片引用（放在题干后面）：」，这行字出现在成品里 | 只给一行 `![](figs/x.png){width=45%}`，不写说明 |
| 结构漂移 | 让它"参考范本"，它只读了个大概 | 结构直接写进规格，不让它自由发挥 |

**得到的结论**：
> 弱模型不猜意图，它执行字面。**规格的措辞就是产物的措辞。**
> 且交付前必须机械验证（grep 得到「答案：」就退回），不能信它"已完成"的自我报告。

## 阶段 2：迁到 DeepSeek 现版本（当前形态）

**变化**：出稿交给能力更强的模型，脚本化流程在本地。分工变成：

```
人（10 分钟）：说清这节课讲什么 + 验算答案
   ↓
模型：按 SKILL 结构模板 + 范本，产出三个 md
   ↓
脚本：建目录 → 转 docx → 三项数字自检
   ↓
人：看自检结果，PASS 就打印
```

**关键决策：把"结构性的事"全部从模型手里拿走，交给脚本。**
建目录、命名、转格式、数公式、数图片——这些不需要判断力，交给确定性代码比交给模型可靠一个数量级。

---

## 阶段 3：规则收敛（2026-10，被打印费逼出来的）

三个用户规则，都是实际用出来的，不是设计出来的：

### 规则 1：学案和作业的解题区只留空白
早期版本会在题下面写「提示：先用 xxx 公式」。结果学生**只看提示，不动脑**。删掉之后，反而开始自己想了。

### 规则 2：教案只写答案 + 解析
第一版教案很"完整"：课前提要、学情判断、本课目标、重难点、时间分配、追问清单、收尾自查、评分点表格。看起来专业，**打印一次十几页**。

用户原话：「打印按页收费，除了答案解析什么都不要放。」

于是全部删掉，只留：

```
**练习1**

答案：$t = 0.5\ \mathrm{s}$。

解析：$h = \frac{1}{2}gt^2$，$1.25 = 5t^2$，$t^2 = 0.25$，$t = 0.5\ \mathrm{s}$。
```

验收标准也变成了数字：**行数 ≤ 200，`$$` 计数为 0，grep 不到「时间分配 / 追问 / 评分点」**。

### 规则 3：docx 文件名必须自带身份
打印出来的纸没有文件夹。一叠纸放在桌上，你分不清哪张是 k67 的物理教案。

规则：`<学生><科目>_<章节>_<学案|教案|课后作业>.docx`，例如 `studentA物理_已学大题专题_教案.docx`。
md 源文件仍用短名（`学案.md`），只有 docx 带身份——因为 md 在浏览器里看，框里本来就显示目录。

## 阶段 4：工具化（把经验变成不可跳过的脚本）

四个脚本对应四个"人一定会忘"的动作：

| 脚本 | 忘了会怎样 |
|---|---|
| `new-lesson.ps1` | 忘建 `figs/`，图没处放；或覆盖已有章节 |
| `build-lesson.ps1` | 忘加 `--resource-path`，图片静默消失；忘自检，公式变成乱码字 |
| `close-lesson.ps1` | 上完的课文件不清理，几章之后目录就找不着东西 |
| `lesson-health.ps1` | 靠人脑记 20 个章节哪个缺文件 |

## 最贵的三个坑（直接损失时间，写在这里让你不踩）

### 坑 1：pandoc 按当前工作目录找图
不是按 md 所在目录。跨目录调用时图片会**静默**变成文字占位——不报错，你自己看 docx 才发现图全没了。一次丢了 18 张图。
修法：`--resource-path="<md所在目录>;<figs目录>"`。

### 坑 2：PowerShell 中文变量名吃掉文件名
```powershell
"$d\$pre学案.docx"     # $pre学案 被当成一个变量 → 未定义 → 空 → 路径塌成 $d\.docx
```
连续两次 Move 撞到同一个目标，**文件被覆盖，丢了**。
修法：`"$d\${pre}学案.docx"`，或者先拼好完整文件名再用 `Join-Path`。**动文件前先断言目标全路径。**

### 坑 3：`.ps1` 不存 UTF-8 BOM
PowerShell 5.1 把无 BOM 的 UTF-8 按 ANSI(GBK) 解析，中文立刻乱码成语法错误（`教案` → `鏁欐`）。
修法：写文件后补 BOM：
```powershell
$c = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p, $c, (New-Object Text.UTF8Encoding($true)))
```

## 一句话总结

> 这个项目真正的技术含量不在"让 AI 会做题"，
> 而在**把结构性的事从 AI 手里抢回来交给脚本，只把判断留给人和模型**。
