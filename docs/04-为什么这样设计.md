# 为什么这样设计

> 每个设计决策背后都有一个具体的、付过代价的理由。这一页解释「为什么是现在这个形态」。

---

## 决策 1：不做模型，只做流程

**放弃的方案**：微调一个教育模型 / 建题库 / 搭 RAG 服务。

**为什么不**：
- 家教备课的难点不在"模型知不知道自由落体公式"，而在**输出格式、答案分发、可打印性**。这些跟模型能力无关。
- 微调需要语料，而我只有两个学生的资料——量级差三个数量级，训出来还不如通用模型。
- 一个有服务器依赖的方案，会让"今晚临时改一节课"变成"先开机等部署"。

**结论**：把不确定性留给模型（它擅长），把确定性交给脚本（它可靠）。

---

## 决策 2：三份文档，而不是一份

**放弃的方案**：一份「完整教案」同时给学生和老师。

**为什么不**：先想清楚一件事——**信息可见性本身就是教学手段**。

- 学生看到答案 → 跳过思考
- 学生看到解法提示 → 照着套，不会自己找路径
- 老师手上没有答案 → 上课要现场算，卡壳
- 老师手上没有解析 → 讲不清为什么错

所以三份文档的**内容差异不是排版问题，是教学法问题**：

| 文档 | 可见什么 | 隐藏什么 | 教学意图 |
|---|---|---|---|
| 学案 | 题干、题型结构、通法、空白解题区 | 全部答案 | 自己动手，认题型 |
| 教案 | 全部答案 + 解析 | 无关的教学法说教 | 讲得清、算得快 |
| 课后作业 | 题干 | 全部答案 | 独立检验，下次课对答案 |

## 决策 3：教案只写答案 + 解析

**第一版不是这样**。第一版教案很"专业"：课前提要、学情判断、本课目标、重难点分析、时间分配、课堂追问清单、收尾自查、评分点表格、易错提醒、批改关注。

**为什么删**：

1. **打印按页收费。** 一份教案十几页，成本直接翻倍。
2. **那些内容没人看。** 上课时不会翻到"课前提要"那一页——你在讲课，不在读教案。
3. **它会挤占注意力。** 教案越厚，真正要看的答案越难找。

**删剩什么**：

```
**练习1**

答案：$t = 0.5\ \mathrm{s}$。

解析：$h = \frac{1}{2}gt^2$，$1.25 = 5t^2$，$t^2 = 0.25$，$t = 0.5\ \mathrm{s}$。
```

**可验证的验收标准**（不是"感觉精简了"）：
- 行数 ≤ 200
- `$$` 独立公式块计数 = 0（全部行内，省垂直空间）
- grep 不到「时间分配 / 追问 / 评分点 / 批改关注」

## 决策 4：脚本负责结构，模型负责内容

这是整个项目最核心的分工线。

| 事项 | 谁做 | 为什么 |
|---|---|---|
| 建目录、命名 | 脚本 | 人会忘建 `figs/`，会覆盖旧稿 |
| md → docx | pandoc | 确定性转换 |
| 数公式、数图片、查占位符 | 脚本 | 人眼看不出 `oMath=0` 是错的 |
| 判题型、拟题目、写解析 | 模型 | 需要语言能力 |
| 验算答案 | **人** | 模型算错是常态，不能省 |

**为什么不让模型做结构**：试过。让它"参考范本"，它只读了个大概，三次输出三种栏目顺序。结构性的东西交给确定性代码，可靠一个数量级。

## 决策 5：答案单独成节写进规格

**这是付过 17 处返工代价的决策。**

失败现象：让模型出稿时，规格里写了

```
题目：一个物体从 1.25m 处自由落下……
答案：t = 0.5s
```

它会**原样把「答案：t = 0.5s」抄进学生版学案**。一次数学 8 处、一次物理 9 处。

**修法**：规格里答案**集中写在独立的一节**，并在节标题上写死约束：

```markdown
## 【以下内容只写入教案，学案和课后作业中不得出现】
练习1 答案：t = 0.5 s
...
```

交付前再 grep 一次 `答案：` 在学案里应为 0 处。**两道保险，因为这个错太贵。**

## 决策 6：docx 文件名带学生 + 科目 + 章节

打印出来的纸没有文件夹。一叠纸放桌上，分不清哪张是谁的。

规则：`<学生><科目>_<章节>_<学案|教案|课后作业>.docx`

md 源文件仍用短名（`学案.md`），因为 md 的浏览场景里，文件列表本身就在目录里，名字短更好找。

**两种场景、两套命名**，不是不一致，是各自适配。

## 决策 7：用 PowerShell，不用 Python

**放弃的方案**：Python + python-docx。

**为什么不**：
- 目标用户是**在 Windows 上备课的家教老师**，不是开发者。PowerShell 开箱可用，Python 需要装环境。
- 核心转换交给 pandoc（成熟工具），脚本只做胶水——胶水用什么语言都行，选零安装的那个。

**代价（必须写在明面上的）**：
- 中文在 PS 5.1 里有一堆坑（BOM、变量名拼接）
- 脚本可读性不如 Python
- 跨平台不友好（只保证 Windows）

如果你在 macOS/Linux：四个脚本逻辑很简单，重写成 bash 或 Python 约 100 行，`scripts/` 里每个文件顶部都写了它做哪几件事。

## 决策 8：不承诺"全自动"

这个项目**故意**留了两个人工环节：

1. **验算答案** —— 模型算错是常态。答案错一份，学生记错一辈子。
2. **看自检结果** —— `PASS` 只说明格式没错，不说明内容对。

**为什么不做成全自动**：全自动意味着把"内容正确性"也交给模型。这件事在数学和物理上不可接受。**能自动化的自动化，判断留给人和模型，验算留给人。**

---

## 一句话

> 这个项目的设计原则只有一条：
> **凡是"忘了就会出错"的事，写成脚本；凡是"需要判断"的事，写进提示词；凡是"错了代价大"的事，留给人。**
